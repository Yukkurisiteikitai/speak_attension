# 0018: 会議モードの主表示を状態中心にし、確度の境界を型で保つ

Date: 2026-09-26
Status: accepted

## 背景

会議モードの中央パネルは、既定で発言のつながりを描く「会議の流れと次の検討」（`MeetingProgressMap`、React Flow によるグラフ）だった。グラフは関係の把握に向くが、画面を開いた瞬間に「今何が決まっていて、何が足りず、次に何をすべきか」を言葉で把握するには一段の読み替えが要る。[UI_DESIGN_REPORT.md](../UI_DESIGN_REPORT.md) の7層評価が指摘するとおり、主画面の第一優先は「今すること」、第二優先は「未決定・危険な不足」であるべきで、グラフはその手段ではなく根拠への経路であるべきだった。

一方、決定グラフ（`meetingDecisionGraph.ts`）とその周辺（`meetingState.ts`、`decisionSupport.ts`）は、既に以下の確度区分を型・状態として保持していた。

- `MeetingNodeState`: `human_stated` / `decided` / `proposed` / `ai_suggested` / `unconfirmed`
- `DecisionMaterialStatus`: `open` / `checked` / `decided` / `deferred` / `accepted` / `irrelevant` / `recheck`（ADR 0017 の判断材料）

しかし中央の主表示がグラフである限り、これらの区分は選択後の詳細パネルでしか読めなかった。

## 決定

1. **会議モードの中央パネルは、既定で新しい `MeetingStateDashboard`（会議の状況）を表示する。** 起動時のモードは引き続き会議モードのままとする。
2. **既存のグラフ／マップは削除しない。** 「流れと次の検討」（進行・質問のワークフローを持つため必須）、「現在状態と根拠」（選択項目からの一段ずつの根拠探索）、「会話マップ」、「整理マップ」は、すべて中央パネル下部の切替から引き続き開ける。ダッシュボードの各項目から「根拠を見る」で「現在状態と根拠」へ遷移し、選択済みノードを直接開く。
3. **Idea Mode は変更しない。** アイデア出しモードでは放射状マインドマップ／階層マップを主役のまま維持する。
4. **新しい view model はゼロから型を作らず、既存の決定グラフとADR0017の判断材料をそのまま分類し直す純粋関数として実装する**（`src/utils/meetingStateDashboard.ts`）。

   - `confirmedDecisions`: `type === "decision" && state === "decided"` のみ。`proposal` 型やその他の状態は決して含めない。
   - `structuralGaps`（構造上の不足・A分類）: 未完了のアクションノードで `owner` または `deadline` が欠けているもの。ルールによる自動検出であり、既存の `topicCoverage.ts` の話題レベルの検出とは別軸（決定グラフのアクション属性を直接見る）。
   - `unresolvedItems`（未確認・未解決・B分類）: 未回答の質問、未採用の提案、`state === "unconfirmed"` のノード。
   - `aiSuggestedChecks`（AIの確認候補・C分類）: `decisionSupport.ts` の判断材料のうち `status` が `open` または `recheck`（ファシリテーターがまだ何も判断していないもの）。
   - `humanConfirmedChecks`（人間が確認した項目・D分類）: 同じ判断材料のうち `status` が `checked` / `decided` / `accepted`（ファシリテーターが明示的に扱ったもの）。
   - `nextActions`: 既存の `selectCurrentActions` をそのまま再利用する。
   - `now`: 「この瞬間に確認・処理すべき1件」を、構造上の不足 → 未回答の質問 → 最優先アクション の優先順で機械的に1件選ぶルールベースの補助表示。Action一覧（右レールの全件表示）とは別の要素であり、これを確定した判断として扱わない。

5. **AI提案は視覚的にも操作的にも弱く扱う。** `aiSuggestedChecks` には根拠への直接ボタンを置かず、「判断材料パネルを開く」という一段階を挟む。「重要」「必須」「危険」という語は AI 提案には付けない。「構造上の不足」だけが、ルールで検出された欠落として明示的に強い表示（警告色）を持つ。
6. **判断変更条件（section 11 の概念）は、今回は独立モデルを新設しない。** `DecisionMaterial.kind === "meeting_fact"` が会議固有の事実からの条件に近いが、現在の実装では他の AI 提案と同じ `aiSuggestedChecks` に入り、`status` が人間により更新されるまで確定扱いにしない。参加者由来の条件を一般的な AI 推論より強く扱う専用モデルは、需要が具体化してから追加する（既知の限界として記録する）。
7. **右レールの `ActionView` は「アクション一覧」に改称する。** 「NOW」という語は中央ダッシュボードの単一項目スポットライトだけに使い、全件リストと混同しない。

## 帰結

- 中央パネルを開いた瞬間に、確定した決定・構造上の不足・未確認・AI提案の別が読める。グラフは選択後の探索先として残る。
- 新しい分類ロジックは既存のノード状態・判断材料ステータスを読み替えるだけで、新しい確定状態を作らない。ルール自体（何が構造上の不足か、何が未確認か）は今回の変更で変わらない。
- 判断変更条件の強い扱いは今回未実装のまま。AIの一般的な確認候補と同じ弱い表示になる制約が残る。
- Cloud上ではLM Studio・Web Speech APIの実接続は検証できない。ルールベースのフォールバックのみを対象に確認した。
