# ADR 0028: 会議のIndexedDB保存とイベント正本

- 状態: 採用
- 日付: 2026-11-18

## 背景

議事録の訂正・撤回・レビュー結果はメモリ上の状態だけでは再読み込み後に失われる。表示テキストを保存すると、意味状態や根拠との不整合を検出・再生成できない。

## 決定

- ユーザーが「この端末に保存」を選んだ会議だけをブラウザーIndexedDBへ保存する。
- IndexedDBには、会議メタデータ、元発言イベント、意味訂正イベント、レビューイベント、再現に必要なレガシー会議イベントとグラフ、およびスキーマ・判定ポリシーバージョンを保存する。
- Canonical、タイムライン、議事録表示は保存イベントから再生成する。保存データのスキーマまたは根拠範囲が不正なら、誤ったProjectionを作らず復元を停止する。
- Markdown / JSON はエクスポートProjectionであり、保存の正本にはしない。
- 保存は明示的な端末操作とし、ネットワーク送信やクラウド同期を追加しない。IndexedDBを暗号化・アクセス制御と説明しない。

## 結果と制約

- 保存した会議は同じブラウザープロファイル内で再読み込み後に再開でき、ユーザーは保存データを削除できる。
- 保存前の会議は再読み込みで失われる。ブラウザーのデータ消去、容量制限、端末障害に対するバックアップはない。
- IndexedDBへの書き込み失敗は画面に表示し、会議を保存済みとは表示しない。
- Canonicalの内部数値revisionは再生順で変わる可能性がある。レビューイベントは根拠・項目ID・意味状態・種別が一致する場合にそのレビュー時点の項目状態を復元する。
- 将来スキーマを変更する際は、明示的な移行関数と旧データのテストを追加する。未対応バージョンを読み飛ばして表示しない。

## 検証

`meetingArchive.test.ts` でイベント再生、レビュー状態・履歴、訂正、撤回、根拠オフセット、未知スキーマ、重複イベント、保存失敗を検証する。実ブラウザーの再読み込み往復と全体性能測定は実装検証時に記録する。
