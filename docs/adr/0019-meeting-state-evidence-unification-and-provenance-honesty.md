# 0019: 状態と根拠の同一画面表示、構造上の不足の範囲修正、確度表現の是正

Date: 2026-09-27
Status: accepted

## 背景

[ADR 0018](0018-meeting-state-primary-surface-and-epistemic-boundaries.md) で `MeetingStateDashboard` を会議モードの主表示にしたが、実際に使ってみると次の問題が残っていた。

1. ダッシュボードの「根拠を見る」は毎回 `MeetingStateMap`（別画面）へ遷移しており、「状態を見る」と「根拠を見る」が分断されていた。
2. `structuralGaps` が `status: "proposed"`（まだ採用されていないアクション案）にも適用され、採用前の案に担当・期限がないことまで「構造上の不足」として警告していた。
3. `now`（NOWスポットライト）が「構造上の不足 → 未回答の質問 → 次のアクション」という固定順で1件を選ぶ処理を、UI上「今すぐ確認すべき」という強い優先度の確定であるかのように見せていた。
4. `decisionSupport.ts` は正規表現によるルール処理であり、AIモデルを呼び出していない。にもかかわらず、その出力を `aiSuggestedChecks` と呼び、UIでも「AIの確認候補」と表示していた。これは実際の由来（provenance）と異なる表示だった。

いずれも [ADR 0018](0018-meeting-state-primary-surface-and-epistemic-boundaries.md) が掲げた「AIやルールが単独で重要度・確度を確定しない」という原則に反する実装上の後退であり、修正する。

## 決定

### 1. 状態と根拠の統合

`MeetingStateDashboard` にインライン根拠パネルを追加した。ダッシュボード内のどの「根拠を見る」ボタンを押しても、同じ画面内に選択ノードの種別・状態・本文・（発言/決定/結果のみ）時刻と発言者・直接の参照先一覧を表示する（`selectedNode` / `selectedNodeParents` props、`src/utils/meetingDecisionGraph.ts` の既存 `selectDecisionParents` を再利用）。画面遷移はしない。

`MeetingStateMap` は削除せず、複数ホップにわたる関係探索が必要な場合にのみ「関係を詳しく見る（根拠マップ）」から明示的に開く advanced trace view として位置づけを変更する。ボタン文言・secondary tab のラベルもこれに合わせて変更した。

### 2. 構造上の不足の範囲

`structuralGaps` は `action.status` が `"decided"` または `"in_progress"`（または未設定）のアクションだけを対象とする。`"proposed"`（未採用の案として手動で戻された場合を含む）は対象外とする。`selectCurrentActions` が「今すること」とみなす集合と一致させることで、二重基準を作らない。テストに `status: "proposed"` かつ担当・期限が両方欠けているアクションが `structuralGaps` に現れないことを追加した。

### 3. NOWの表現

`NowSpotlight` に `reason: string` を追加し、なぜその項目が選ばれたかを一文で示す。UI文言を「次にやること」から「次に確認できること」「対応候補のアクション」へ弱め、キャプションに理由を添えて「ルールが選んだ一例です。重要度を確定するものではありません。」と明記する。「今すぐ確認すべき」という命令的な文言は削除した。選定順位（構造上の不足 → 未回答の質問 → 次のアクション）自体は変更しない。新しい優先度エンジンは作らない。

### 4. 確度表現の是正（provenance）

`decisionSupport.ts` はルールベースであり、AIモデルを呼び出さない。そのため view model のフィールド名を `aiSuggestedChecks` から `systemSuggestedChecks` に、UI見出しを「AIの確認候補」から「追加で確認できること」に変更した。現時点では AI 由来かルール由来かを区別するデータを持たないため、どちらか一方を偽って主張しない中立的な表現を選ぶ。将来 LLM 由来の候補を追加する場合は、由来を区別できるデータモデルを別途設計する（本ADRの対象外）。

## 帰結

- ダッシュボードは「状態 → その場で根拠 → 必要なら詳しい関係探索」という一本の流れになる。
- 構造上の不足は、実行段階にあるアクションだけを対象にする、より狭いが正確な警告になる。
- NOWは依然としてルールによる1件選択だが、UI表現は「候補」であって「決定された重要度」ではないことを明示する。
- 「AI」という語を、実際にAIモデルを呼び出していない処理の出力に使わない。
