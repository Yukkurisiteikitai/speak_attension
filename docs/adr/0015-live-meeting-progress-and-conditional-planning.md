# ADR 0015: 会議の進行・考えの収束・条件付き検討計画を一つのマップにつなぐ

日付: 2026-09-11

## 背景

キーワードのグルーピングだけでは、会議がどう進み、どの理由と比較から考えがまとまったのかを説明できない。会話ツリー、決定の逆参照、不足点パネルが分離しているため、質問への回答も次の検討につながっていなかった。ユーザーの要求に従い、会議中の思考過程と次の検討の連動を製品の中心にする。

## 決定

- 起動時は会議モードの「流れ・次の検討」を表示する。既存のアイデア出し、現在状態・根拠、会話マップ、整理マップも利用できる。
- 音声・手入力・リプレイの共通ストアで、発言の処理直後に不足点と検討予定をルールで再評価する。リアルタイムの事実・決定グラフにLLMを介在させない。
- マップは会話ツリーと決定の参照から、発言番号を付けた課題・理由・提案・別案・決定を配置する。比較対象を残し、明示された案名が一意ならその提案へ決定を接続する。実行結果の手動更新も対象アクションの枝に表示する。
- 予定は出典発言に付く質問と、確認できた場合／追加確認が必要な場合の2分岐として保持する。実際の発言と予定を色・点線・日本語ラベルで区別する。
- 操作者が問いを選んで回答を記録すると、回答を元の問いへ接続する。選択した分岐を新しい検討項目にし、回答から次の問いへ進める。保留・再開・再回答を扱い、原発言と複数の回答参照を保持する。回答記録と問題の解決は同義にしない。担当・期限の確定は既存の対象アクション更新で行う。
- ローカルLM Studioにモデルが設定されていれば、最大3件の未回答質問と上限を設けた根拠・直近発言を非同期に渡して、質問・理由・条件付き予定を具体化する。AIに事実・決定の変更権限は与えない。JSON・参照ID・2分岐を検証し、失敗時はルール提案を保持する。
- 同時レビューは1件。3秒周期で更新の有無を確認し、同じ版を繰り返し処理しない。20秒で中断する。会議の版が変わった応答、リセット前・設定変更前の応答は適用しない。
- 時間スライダーは発言アーカイブの先頭から指定件数までの思考マップを再表示する。過去表示に現在の予定を混ぜない。これは過去のAI表示・手動レイアウトの完全な復元ではない。
- MarkdownとJSONに発言順、思考のつながり、問い・予定・回答参照を含める。DB保存、クラウドAI、音声保存は追加しない。

## 制約と検証

関連の推定はルールによる候補であり、暗黙の話題転換・複雑な否定・曖昧な案の指示を完全には解釈できない。未回答の提案は、別案が採用されても自動的に却下しない。モデルの処理中に会議が更新され続ける場合は、古い応答を捨て、ルール提案を表示し続ける。

受け入れテストは、議題→課題→理由→A案→B案→A案採用、回答→追加確認分岐、保留・再回答、担当更新、AI失敗・遅延・リセット、長短ラベルの非重複配置を対象とする。変更後は `npm run check` と `npm run build` を実行する。
