# ADR 0027 根拠付き議事録と確認イベント

- 日付: 2026-11-18
- 状態: 採用
- 関連: [ADR 0018](0018-meeting-state-primary-surface-and-epistemic-boundaries.md)、[ADR 0022](0022-semantic-core-and-central-promotion-policy.md)、[ADR 0023](0023-realtime-first-semantic-core-fast-and-refinement-paths.md)

## 採用した設計

発言の原文と文字範囲、話者、時刻を維持する。Fast Path は独立したタスクを意味単位に分け、局所文脈から明示的な日時合意、撤回、条件、異議、差し替えを関係として出力する。Canonical reducer は発言、関係、人による訂正を解決する。撤回・差し替えを有効項目の索引から除き、関連タスクの確認条件を再評価する。議事録のIDには意味単位IDを使い、種別や表題の訂正をまたいで維持する。

確認イベントは既存の発言イベントログに追記する。議事録は Canonical と確認イベントを組み合わせた投影である。議事録、確認キュー、プレビュー、Markdown / JSON、タイムラインは同じ項目の意味状態と確認状態を読む。手動訂正、保留、確認と取り消しには、項目の版と変更前後の記録を残す。一括確認は対象全件を同じスナップショットで再検証してから適用する。

意味上の合意と確認状態を分ける。低リスクの選択確定、話者が判明している明示的な日時合意、本人の期限付きの引き受けを優先して自動記録する。曖昧さ、未解決条件、異議、必須情報の欠落、承認権限がある場合は確認が必要になる。正式な権限を検証できない環境では、対象を議事録上も確定できない。記録の更新はセッション内のイベントに閉じる。

進行中の既存ダッシュボード、決定グラフ、分析レポートは従来の投影を使用する。過去の会議を再読み込みする永続化はない。規則の関係解決は明示的な参照と近い文脈に限られ、対象が複数ある撤回、話者不明の合意、語彙外の権限表現には追加の確認が必要になる。

## 検証方法

変更前の基準はこの作業ツリーの `8a1035b`。既存コーパスは変更せず `npm run semantic:eval` で比較した。20ケースで Semantic Core の決定・タスクの適合率と再現率は変更前後とも100%、偽陽性は0件。これは既存コーパスの抽出結果を測った値。

[ブラウザ評価スクリプト](../../scripts/evaluateMeetingMinutesBrowser.js) の8件の合成シナリオでは、議事録と意味状態を別に採点した。変更前は議事録キューが存在しないため、比較には Canonical の有効な決定・アクションを使う。変更後は意味上の合意と記録済みの項目を別々に集計する。

| 指標 | 変更前 | 変更後 |
| --- | ---: | ---: |
| 決定・タスク・日程の抽出適合率 | 3/6（50%） | 5/6（83%） |
| 決定・タスク・日程の抽出再現率 | 3/5（60%） | 5/5（100%） |
| 誤確定率 | 3/6（50%） | 0/4（0%） |
| 根拠発言IDを追跡できる項目 | 6/6 | 10/10 |
| 正確な文字範囲を追跡できる項目 | 旧投影の項目出力にはなし | 10/10 |
| 8シナリオの確認待ち | キューなし | 合計5件 |

変更後の抽出偽陽性1件は会議での予算合意を示す言い回しで、承認権限が未確認のため議事録では要確認に留まる。訂正後に Canonical、タイムライン、プレビューを比較し、元発言・履歴を保持したまま有効な決定が消えることをストアテストと Orca の実画面で確認した。実会議の録音と人による確認時間は未計測。

Orca のブラウザで同一の合成発言を100件ずつ処理した。ウォームアップを除外し、取り込み700件、投影70回、終了処理7回の p50 / p95 を比較した。投影は変更前がタイムラインのみ、変更後が議事録とタイムラインを含む。計測には画面描画や人間の操作時間を含めていない。

| 処理 | 変更前 p50 / p95 | 変更後 p50 / p95 |
| --- | ---: | ---: |
| 発言の取り込み | 0.2 / 0.4 ms | 0.3 / 0.5 ms |
| 投影 | 0.0 / 0.1 ms | 0.1 / 0.2 ms |
| 会議終了 | — | 0.2 / 0.3 ms |

Monika の既存検証で、Capture 欠落時にも成功コードを返す場合が確認された。参照の確認では日付を含まない `根拠付き議事録` 見出しを選び、両端の Capture ID、非空の Region、出力行数を確認する。Monika が確認するのは参照範囲と内容の変化。実行時の状態遷移はテストとブラウザで別に確認する。PoC の手順と生データは Googd の `docs/operations-findings.md` と `evaluation/2026-11-14/` にある。

今回の隔離コピーでは、STATE の議事録節から投影関数、投影関数からストアテストの2本を確認した。4端点すべてで Capture ID と非空の選択範囲が解決し、保存直後の check は2件とも差分なしだった。
