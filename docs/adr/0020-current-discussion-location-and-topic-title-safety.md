# 0020: 「現在地」を状態の部品と別の概念にし、壊れた論点タイトルを防ぐ

Date: 2026-09-27
Status: accepted

## 背景

ADR 0018/0019 で会議モードの主表示を「会議の状況」ダッシュボードにしたが、実際に使うと次の問題が残っていた。

1. ダッシュボードは「決定済み」「構造上の不足」「未確認」「次のアクション」という**状態の部品**を並べるだけで、「議論はいま何をしている段階か」「何が解ければ前進するか」という**現在地**が一目で分からない。
2. decision/actionがまだ存在しない初期〜中間段階では、画面の大半が「0件」「ありません」という空状態の説明になり、実際に存在する情報（未解決の問いなど）より目立っていた。
3. 「現在の判断テーマ」に表示される `currentTopic.title` が、抽出の不具合で「のステップの修正」のような助詞始まりの壊れた断片になることがあった。
4. 「このステップが完了することは何を意味するか」のような、丁寧形（ですか/ますか/でしょうか）を使わない素朴な疑問文が、決定グラフの質問検出パターンに引っかからず、未解決の問いとして扱われなかった。

## 決定

### 1. 現在地（`CurrentDiscussionState`）を状態の部品とは別の概念として実装する

新しい純粋関数 `src/utils/currentDiscussionState.ts` の `buildCurrentDiscussionState` を追加した。入力は既存の `MeetingGraph`（現在の議題ノード）、`currentTopicId`、決定グラフ、発言アーカイブのみで、新しい確定事実は作らない。出力は次を持つ。

- `topicTitle` / `topicTitleSource`: 表示用の論点タイトルと、その出典（`extracted_topic` / `unresolved_question` / `recent_utterance` / `unknown`）。
- `stage`: 会議が今どの段階にあるかを、既存の決定グラフのノード種別（課題・理由・提案・決定・アクション・質問）の有無から機械的に分類したもの（10種類、詳細は次節）。
- `unresolvedQuestion`: 現在の論点に関連する未回答の質問ノード（実在するノードそのもの、推測ではない）。
- `progressCondition`: 「次に前進する条件」。stageに対応する定型文をテンプレートで生成したもので、常に「推定」であることをUIで明示する。
- `decisionThemeTitle`: 決定が実際に存在する場合だけ設定される「判断テーマ」。すべての会議が判断をしているわけではないため、決定が無ければ`null`（UIでは「なし」）。

### 2. stage分類のルール（Sonnetが設計、既存データからのみ導出）

現在の議題が最後にアクティブになった時刻（`lastActivatedAt`）以降に作られた決定グラフのノードだけを対象にする（簡易な近似であり、証明された因果関係ではないことをコードコメントに明記）。その範囲で、以下の優先順位で1つのstageを選ぶ。

1. 未回答の質問がある → `resolving_question`（未解決の問いを確認中）
2. アクションがあり、`in_progress` → `in_progress`（実行中）
3. アクションがあり、担当または期限が欠けている → `clarifying_execution`（実行内容を具体化中）
4. アクションがある（上記以外） → `decided`（決定済み）
5. 決定がある（アクションはまだ無い） → `decided`
6. 提案が2件以上 → `comparing_options`（選択肢を比較中）
7. 提案が1件 → `generating_options`（選択肢を出している）
8. 課題と理由の両方がある → `organizing_reasons`（原因・理由を整理中）
9. 課題だけがある → `confirming_problem`（問題を確認中）
10. 対象範囲に何も無い → `unknown`（状態を特定できません）
11. 上記のどれにも当てはまらない活動（根拠・懸念・リスクのみ等） → `ambiguous`（複数の検討が進行中）

候補として検討した「決定待ち」は、既存データから安全に区別できる基準が無かったため実装しなかった（既知の限界）。単純な優先順位だけで誤ったstageを選ばないよう、質問の有無を最優先にしている。

すべてのstageとprogressConditionは、UI上で「会話の内容から機械的に分類した目安です。断定ではありません。」というキャプションと共に必ず表示する（`CurrentDiscussionCard`）。

### 3. 壊れた論点タイトルを防ぐ（根本原因の修正＋表示層のフォールバック）

**根本原因**: `src/utils/topicExtraction.ts` の `tokenize()` が「問題」「は」などを正規表現でインフィックス除去する際、前後の文字列が結合し、助詞（「の」など）で始まる断片が残ることがあった（例: 「問題のステップの修正」→「のステップの修正」）。`cleanupPhrase()` に、助詞で始まる場合はそれを取り除く処理を追加した。回帰テストを `topicExtraction.test.ts` に追加。

**表示層のフォールバック**: 上記の根本修正後も、抽出結果が短すぎる・助詞始まりである等で壊れる可能性はゼロにできないため、`buildCurrentDiscussionState` は以下の順でタイトルを決める。

1. 抽出済みの現在の議題タイトル（`isWellFormedTopicTitle` を満たす場合のみ）
2. 現在の未解決の問いの短縮表現
3. 直近の発言の安全な抜粋（40文字）
4. 「論点を特定できません」

`isWellFormedTopicTitle` は、2文字未満、または「の/を/が/は/に/で/と/も/へ」で始まる場合を壊れたタイトルとみなす。LLMは使わない。

左レール「会議プロセス」の現在の議題表示も、同じ安全なタイトルを使うよう修正した（従来は `topicEngine.currentTopic.title` を直接表示しており、同じ不具合の影響を受けていた）。

### 4. 質問検出パターンの拡張

`src/utils/meetingDecisionGraph.ts` の `QUESTION_PATTERN` は、丁寧形の疑問文末（ですか/ますか/でしょうか）と `?`/`？`、および「なぜ/どうして/どういう/何が/誰が」で始まる文しか質問と認識しなかった。「このステップが完了することは何を意味するか」のような、疑問語（何/誰/いつ/どこ/なぜ/どう/どちら/どの）を含み「か」で終わる素朴な疑問文も質問として認識するよう拡張した。誤検出を避けるため、単に「か」で終わるだけでは質問とみなさず、疑問語の存在を必須とする。既存のテストスイート（357件）に回帰は無い。

### 5. UIの統合と簡素化

- 中央ダッシュボードの先頭を、旧「現在の判断テーマ」見出し + NOWスポットライトから、新しい `CurrentDiscussionCard`（現在の論点・現在地・未解決の問い・次に前進する条件・判断テーマ）に置き換えた。NOWスポットライト（ADR 0019で文言を弱めたもの）は、現在地カードと役割が重複するため中央パネルからは撤去した。裏側の `now`/`NowSpotlight` セレクターとそのテストは変更していない（他の用途のために残す）。
- 「今決まっていること」「構造上の不足」「未確認・未解決」「追加で確認できること」「次にやること」の各セクションは、0件のときは新しい `CollapsibleZeroState` でコンパクトな1行表示にし、「表示」で個別に、または「すべての状態を見る」でまとめて展開できる。件数が1件以上のセクションは常に全展開のまま変更しない。

## 帰結

- 中央パネルを開いた瞬間に、論点・段階・未解決の問い・前進条件が一体で読める。個々の状態部品（決定・不足・アクション）はその下に残る。
- stage分類とprogressConditionは既存グラフの機械的な読み替えであり、新しい確定状態を作らない。判断テーマは決定が実在するときだけ表示され、「判断していない会議」を「判断テーマなし」と正直に示す。
- 質問検出パターンの拡張は既知の限界を残す（複雑な暗黙の疑問文、話し言葉特有の省略には対応しない）。
