## LLM通信が失敗したとき

会議の質問・検討予定の自動レビューもLM Studioのみを使う。モデル未設定時はルール提案、失敗・20秒超過時は理由を表示してルール提案で継続する。「分析」タブのAI設定でモデルを設定できる。

1. アプリの「接続確認」を実行する。
2. LM Studioが起動済みで、対象モデルがロード済みか確認する。
3. 接続先とモデルIDを確認する。
4. 当日のログを確認する。

```sh
tail -f logs/runtime-$(date +%F).jsonl
grep -E 'llm\.(models|chat)\.(failed|loaded|completed)' logs/runtime-$(date +%F).jsonl
```

| イベント | 意味 | 次に確認すること |
| --- | --- | --- |
| `llm.models.failed` | 接続確認またはモデル一覧取得に失敗 | LM Studio起動、接続先、CORS、HTTPエラー |
| `llm.chat.failed` | LLM後処理の実行に失敗 | モデルID、応答上限、JSON形式、HTTPエラー |
| `llm.models.loaded` | モデル一覧の取得に成功 | モデル数と自動設定されたモデルID |
| `llm.chat.completed` | LLM後処理が完了 | 処理対象の画面結果 |

LLMが失敗しても、アイデア抽出・会議処理はルールベースで継続する。

## ログとDiscord

- ログの保存先: `logs/runtime-YYYY-MM-DD.jsonl`
- フロントエンドログ: ブラウザーが `/api/logs` を通じて保存する。
- バックエンドログ: サーバー起動、Discord送信成功・失敗を同じファイルへ保存する。
- Discord Webhook URL: `.env` の `DISCORD_WEBHOOK_URL`。URLを画面、ドキュメント、ログへ書かない。
- 会議レポート: 会議画面で生成後に「Discordへ送信」。
- 技術管理レポート: `npm run report:discord`。

## 変更時の必須事項

- `src/utils/` のロジックは純粋関数に保ち、対応するテストを更新する。
- UIまたはビルド設定に触れたら、`npm run check` と `npm run build` を実行する。
- 実装状態の変更は `STATE.md` へ反映する。
- 新しい方針は新規ADRに記録する。既存ADRは変更しない。
- LLMはLM Studioのみを使い、新しいLLM機能にはルールベースfallbackを付ける。

## 2026-09-11の作業記録

### 会議の進行と次の検討の統合

製品の中心を「会議がどう進み、考えがどうまとまったかと、次に何を確認するか」に変更した。起動時の会議モードで「流れ・次の検討」を開く。仕様・制約は `STATE.md`、設計理由は [ADR 0015](adr/0015-live-meeting-progress-and-conditional-planning.md) を参照する。

手動確認は画面上部の「会議の発言を追加」に、次の順で入力する。

1. 今日は連絡方法について決めます
2. 候補者への連絡が遅い問題があります
3. 理由は担当が不足しているからです
4. A案でメールを自動化しましょう
5. 別案としてB案で電話を増やしましょう
6. A案を採用します

確認する体験：課題・理由と両案を残したまま、採用発言がA案へ接続する。問いを選んで根拠と2本の条件付き予定を開き、回答を入力する。「まだ分からない」を選んで記録すれば追加確認の分岐が次の検討になる。時間スライダーを4発言目へ戻すとB案と採用発言が消え、「現在の会議に戻る」でライブ状態へ戻る。Markdown/JSONには元発言と質問・予定・回答参照が含まれる。

質問は手入力・音声・リプレイに連動して再評価される。モデル設定時だけ自動で非同期レビューを行う。AI応答より会議の更新が速い場合は古い応答を捨ててルール提案を維持する。回答の記録と、担当・期限の確定は別の操作。関係の推定はルールによる候補であり、曖昧な発言を完全に理解するものではない。

音声の回答は、問いの「次の発言を回答として接続」で回答先を先に指定する。次の1セグメントを接続して指定を解除する。発言がバッファに残っている場合は、先に音声入力を停止してバッファを反映してから指定する。

検証結果: `npm run check` 成功（49ファイル・291テスト）、`npm run build` 成功。ビルドにはJavaScriptチャンクが500kBを超える警告が残る。実ブラウザーでの画面操作・音声認識と、実際のLM Studioでの提案品質は未確認。AI通信の成功・失敗・20秒タイムアウト・古い応答の破棄はモックを用いたテストで確認済み。

### 以前の現在状態・根拠への接続

p.md の「現在状態から根拠へ戻れる」体験を、実際の画面操作まで接続した。

- アイデア出し画面で中央マップのキーワードを選ぶと、右レールの「アイデアの根拠と現在地」も同じキーワードを表示するようにした。
- 右レールで選んだキーワードも中央マップ側の確認対象として保持し、採否操作とは分離した。
- 会議モードの3種類のマップ切替（現在状態・根拠／会話のマップ／整理マップ）と入力ドックのタブが横一列に表示されるよう調整した。
- 状態の説明は `docs/STATE.md` に反映済み。

検証結果: `npm run check` 成功（45ファイル、268テスト）、`npm run build` 成功。

次担当者は `npm run dev` で起動し、会議モードの「現在状態・根拠」とアイデア出し画面のキーワード選択をブラウザーで確認すること。音声はブラウザーの Web Speech API に依存するため、手入力でも同じ経路を確認できる。

## 2026-09-09の作業記録

`plan.md` の「Meeting State / Decision Graph」優先スライスを実装した。既存の `topicEngine` と `decisionGraph` を維持し、発話を受けるたびにルールベースで決定グラフを増分更新する構成にしている。

- 疑問文、否定、仮定、未確認の推測を決定済みアクションへ昇格させない判定を追加した。明示的な話題転換以降は、それ以前の根拠や提案を新しい決定へ接続しない。
- `src/components/ActionView.tsx` の「NOW / 今すること」を、アクションから決定・理由・根拠・元発言へ一段ずつ開くUIに変更した。元発言には時刻と発言者を表示し、未決定の提案・質問・未確認項目も折りたたみ表示する。
- `src/types/topic.ts` と `src/utils/topicEngine.ts`、`src/hooks/topicEngineStore.ts` を更新し、トランスクリプトのメタデータを決定グラフまで渡すようにした。
- `src/utils/meetingDecisionGraph.test.ts` と `src/utils/topicEngine.test.ts` に、一般的な行動、因果関係、担当・期限、話題境界、未確認状態、話者・原文保持、循環グラフの逆向き探索を追加した。
