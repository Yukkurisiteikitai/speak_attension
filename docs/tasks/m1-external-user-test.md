# M1 第三者利用テスト準備

Issue #29に対応する、開発者以外の利用者による根拠付き議事録の受け入れテスト手順。テスト参加者や会議内容はまだ確保していない。公開URLのバージョンとプライバシー表示を確認するまでは実施しない。

## テストの目的

第三者が開発者の操作補助なしで、会議を進行し、議事録候補の根拠を確認し、訂正または保留し、保存・再読み込み・復元・出力・削除を完了できるかを調べる。抽出精度やFalse Commitment Rateの評価とは別に記録する。

## 参加者への説明

- 現段階はユーザビリティ確認で、サービスの継続提供やデータ保全を保証しない。
- IndexedDB保存は同じブラウザー・端末内のみで、暗号化、アクセス制御、バックアップ、同期ではない。
- 実会議の音声や発言を使う場合、会議参加者全員に記録方法とブラウザーの音声認識の取り扱いを説明し、必要な同意を得る。
- 初回の操作テストは、機密・個人情報を含まない合成発言を手入力する。合成データはテスト終了後に削除する。
- 参加は任意で、途中で中止できる。操作画面やエラー記録に個人情報を含めない。

## 実施手順

1. 公開URL、対象リリース、テスト端末・ブラウザーを記録する。
2. 参加者には操作目標だけを伝え、説明を追加せず完了まで観察する。
3. 合成発言を入力する。例: 「今日は候補の選定について話します」「A案を採用します」「ただし予算の確認が必要です」「佐藤さんが金曜日までに見積もりを確認します」。
4. 会議を終了し、各項目の根拠発言・時刻・状態を確認する。
5. 少なくとも1件を訂正または保留にし、状態が画面に反映されることを確認する。
6. 会議を端末内保存し、再読み込み後に一覧から復元する。
7. 復元後の状態・根拠を確認し、MarkdownとJSONを出力する。
8. 保存済み会議を削除し、一覧から消えたことを確認する。
9. 合成データ以外を使った場合は、テスト用記録・出力ファイルも合意した方法で削除する。

## 記録票

各回について、会議内容を記録せず以下だけを記入する。

| 項目 | 記録 |
|---|---|
| 利用者コード（匿名） | |
| 端末・ブラウザー | |
| 公開URL上の確認済みコミット | |
| 説明なしで完了した工程 | |
| 開発者の助言が必要だった操作 | |
| 保存・復元・出力・削除の成否 | |
| 迷った表示・誤解した表現 | |
| 所要時間（会議終了から出力まで） | |
| データ削除の確認 | |
| 利用者の自由記述 | |

録音、発言本文、個人名、議題は記録票に残さない。評価ラベルが必要な場合は、別途同意を得たうえで匿名化し、[議事録評価データ形式](../MEETING_EVALUATION_FORMAT.md)に従う。

## 判定と次の行動

- **重大失敗:** 未確認項目が確定表示される、保存・復元で訂正状態が失われる、別項目の根拠を表示する、またはデータ削除が確認できない。M1の外部利用を止めて修正する。
- **操作失敗:** 誤操作・説明依存・復元方法の誤解が起きる。該当導線を直して再試行する。
- **操作成功:** 利用者が一連の流れを自力で完了する。理解度、所要時間、継続利用意向を別々に記録する。

小規模な初期観察として5人・合計10回程度を目安にできるが、統計的な代表性を主張しない。全員の同意と、実施後のデータ削除確認を優先する。
